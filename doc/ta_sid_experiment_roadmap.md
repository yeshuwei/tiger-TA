## 三、核心新增模块：L_trans 是什么、为什么加

### 3.1 当前方案（基础版）的隐性不足

当前方案做了融合输入：

```
Input = [Content_emb; Behavior_emb] → RQ-VAE → SID
```

提升的逻辑链是：

```
行为嵌入改变 fused embedding → 改变 RQ-VAE 码本分配 → 产生更符合行为模式的 SID → T5 更好预测
```

这是一个**间接路径**——行为信号经过两层量化（RQ-VAE 的残差量化 + Sinkhorn 去碰撞）后才影响到最终的 SID 空间，信号在这个过程中可能被稀释。

更重要的是，**RQ-VAE 的训练目标并不关心"有转移关系的商品在量化空间里是否接近"。** RQ-VAE 只负责重建 fused embedding，至于洗发水和护发素的编码向量是挨着还是远离，对损失函数没有影响。

### 3.2 L_trans 做什么

L_trans（转移感知对比损失）把上面那条间接路径变成直接路径：

```
间接（当前方案）：行为→改输入→改码本→可能让转移对靠近→T5受益

直接（加 L_trans）：行为→直接要求转移对的编码在量化空间中靠近→T5受益
```

数学形式：

```
L_trans = - ∑_{(i,j)∈E} log( exp(sim(z_i, z_j)/τ) / Σ_n exp(sim(z_i, z_n)/τ) )
```

- 正样本对 (i,j)：在用户序列中经常一起出现的商品 pair（从 transition matrix 中采）
- 负样本 n：随机选的不相关商品
- z_i, z_j：量化后的编码向量
- τ：温度系数，控制聚类的松紧

**直观理解：** 这个损失告诉 RQ-VAE "如果你见到两个经常一起出现的商品，请把它们的编码向量放近一些"。

### 3.3 加 L_trans 的预期收益

| 维度 | 预期 | 原因 |
|:----|:----|:-----|
| 主指标（NDCG@20） | +1~5% 额外提升 | 转移关系直接在量化层编码，信号不稀释 |
| 长尾商品 | 提升更明显 | 低频商品借助相邻高频商品获得更好的空间位置 |
| 冷启动 | 迁移更平滑 | 新商品的 behavior 映射到已有的转移结构上 |
| Codebook utilization | 可能提高 | 对比损失把正样本对拉近，减少了散落孤立的 codeword |

### 3.4 如果 L_trans 无效呢？

L_trans 不一定在所有数据集上都有效。可能的原因：

- τ 温度没调好 → 正负样本对比度不够
- 负样本采样方式不对 → 对比信号太弱
- 该数据集序列结构简单 → 转移关系的信息增量已经被融合输入吃掉了

这是为什么需要**线 B 先在一个数据集上调通**，再决定是否全面铺开。


**预计耗时：** ~8h

### 线 B：L_trans 开发与验证（与线 A 并行）

#### 线 B 第 1 步：L_trans 代码实现

需要修改的文件和工作量评估：

| 文件 | 修改内容 | 工作量 |
|:----|:---------|:------:|
| `rqvae/trainer.py` | 在 loss 计算中加入 L_trans 项 | ~3h |
| `rqvae/main.py` | 增加 `--lambda_trans`、`--tau` 等参数 | ~0.5h |
| `rqvae/build_transition_graph.py` | 额外输出正样本对列表 | ~1h |
| 新文件 `rqvae/trans_loss.py` | 对比学习采样器 + loss 函数 | ~3h |

**关键设计问题（建议代码实现时考虑）：**

1. **正样本采样：** 从 PPMI 矩阵取 top-K 高频转移对作为正样本？还是从用户序列中实时采？
   - 推荐：**预计算高频对**（PPMI > 阈值），训练时从中 batch 采样
   - 原因：避免每次 forward 都读 transition matrix

2. **负样本采样：** batch 内负采样 vs 全局随机采样？
   - 推荐：**batch 内负采样**（infoNCE 标准做法），辅以部分随机负样本
   - 原因：简单高效，τ 调节即可

3. **L_trans 的权重 λ：** 初始值建议设为 0.1（重建损失为主，对比损失为辅）

#### 线 B 第 2 步：在 Toys 上调参验证

| 超参数 | 建议扫描 | 说明 |
|:------|:---------|:-----|
| λ（L_trans 权重） | [0.01, 0.05, 0.1, 0.5] | 对比损失占整体 loss 的比例 |
| τ（温度系数） | [0.07, 0.1, 0.2, 0.5] | 越小越硬聚类，越大越软 |
| 正样本 top-K | [5, 10, 20] | 每个 item 保留多少高频转移对 |

**选择 Toys 的原因：**
- 数据量和训练时间适中（~8h/轮）
- 已有 baseline 和 TA-SID 的对照结果
- 提升空间 3.9%，如果 L_trans 能把提升推到 5-8%，效果就很明显

#### 线 B 第 4 步（如果 L_trans 有效）：加入 L_balance

L_balance（码本均衡损失）的目的是防止所有商品都编码到同一个 codeword：

```
L_balance = Σ_l KL(q_l(c) || U(c))
```

- q_l(c)：第 l 层 codebook 的实际使用分布
- U(c)：均匀分布（希望每个 codeword 被用到相同次数）

这个损失实现简单（~2h），通常和 L_trans 配合使用——L_trans 把正样本拉近，L_balance 防止拉近导致大家都挤到同一个码上。

## 八、附录：L_trans 代码设计思路（开发者备忘）

### 数据流

```
build_transition_graph.py
  └→ 输出 pos_pairs.parquet（高频转移对列表）

trainer.py (修改后)
  ├→ 加载 pos_pairs
  ├→ 每个 batch：
  │    ├─ L_recon = MSE(h, h_hat)
  │    ├─ 采样正样本对 (i,j) ← 从 pos_pairs 中查当前 batch 里的配对
  │    └─ L_trans = contrastive_loss(z_i, z_j, z_neg)
  │         z_i, z_j：量化向量（来自 RQ-VAE 的中间输出）
  │         z_neg：batch 内其他样本
  └→ L_total = L_recon + λ·L_trans
```

### 关键实现细节

1. **取哪个层的量化向量？** 建议取最后一层的残差向量和（$\hat{z}$）或所有层的 concat，前者更简单
2. **正样本如何对齐到 batch？** 维护一个 `item_id -> 高频邻居列表` 的 dict，前向时查
3. **负样本用谁？** batch 内除了正样本以外的其他样本。标准 infoNCE 做法
4. **是否需要 symmetric loss？** 不需要，方向不重要（i→j 和 j→i 都是正样本）

如果决定动手加 L_trans，可以开始修改 trainer.py 和 main.py 了。要不要先看看当前的 trainer.py 结构？我帮你估算具体改哪些位置。

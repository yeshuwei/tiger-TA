# E46 第二创新（Adaptive Coarse-Level Capacity Allocation）推翻与保留裁定（2026-09-04）

> **一句话裁定：** "自适应扩容"作为**方法卖点**被推翻——Toys 的 L0 塌缩不是"固定 256 容量不足"的
> 系统性属性，而是 **seed=2024 单次训练的分配崩坏**；把 256 换成一个健康种子（或扩容到 512 落到健康
> 状态）效果几乎一样（NDCG 0.0372 vs 0.0381，无统计差异）。**判据 z-gap 的诊断价值保留**，且因
> "坏码本 recon 不可见、只有它揪得出"而**更强**；被推翻的是"扩容动作"与"容量剂量-响应"叙事。
> 本文档是第二创新相关主张的**权威裁定 + 修改索引**：各文档凡与本裁定冲突处，以本文档为准。
>
> 证据：E45 [e45_toys_multiseed_collapse.md](e45_toys_multiseed_collapse.md)（多种子量化端 + T5 推荐层）。

## 1. 原来的第二创新主张（E43，现被推翻）

"Adaptive Coarse-Level Capacity Allocation"：粗层码本容量 K0 由数据通过 z-gap 反馈闭环自适应决定。
- **观测支撑**：Toys 在固定 256 上 L0 只用 62/256 码（24%），z-gap=0.0931（丢 9.3% 转移 AUC），
  T5 NDCG@20 0.0367；扩容到 512 后 z-gap→0.0045、NDCG→0.0381（+3.8%）。
- **叙事**：Toys = "容量不足态"（容量性瓶颈），256 系统性不够 → 该数据集需要 K0\*=512。
- **卖点**：① 判据 z-gap 精确（6 数据集全对）；② 扩容动作修复容量不足；③ 推荐层 +3.8% 一致性转正；
  ④ 量化探针平台（512）预测下游平台（传导一致性）；⑤ 自适应结果因数据而异 {256,256,512}。

完整原文见 [e43_summary.md](e43_summary.md) 与 [e43_adaptive_experiment.md](e43_adaptive_experiment.md)。

## 2. 推翻的实验证据（E45，两个实验）

### 2.1 量化端多种子：Toys 塌缩是 seed=2024 的偶然（结果 B）

| RQ-VAE seed | L0 用码 | xq[full] AUC | z AUC | **z-gap** | 判定 |
|---|---|---|---|---|---|
| **2024**（既有锚点） | **62/256 (24%)** | 0.8724 | 0.9656 | **0.0931** | 塌缩 |
| **2025** | 194/256 (76%) | 0.9672 | 0.9688 | **0.0016** | ✅ 健康 |
| **2026** | 151/256 (59%) | 0.9654 | 0.9691 | **0.0037** | ✅ 健康 |

同数据、同配置、仅换 RQ-VAE 种子 → 码本质量在"塌缩"与"健康"之间剧烈摆动。
**Toys 不是系统性需要 512；是 seed2024 恰好踩中坏的码本分配。**

### 2.2 推荐层 T5：健康 256 ≈ 512（判 (a)）

seed2025 健康 256 codes → T5 3-seed（tag `rq2025`）：

> ⚠️ **2026-09-09 provenance 订正**：本表 0.0367 / L0=62 出自**孤儿 codes**（主表 Toys codes 文件无法从任何现存 ckpt 复现，行级一致率最高 29.3%），作为 Toys **正式结果已作废**；本处仅作"塌缩实例"历史对照保留。Toys 正式主结果 = NDCG@20 **0.0377±0.0007** / R@20 0.0911±0.0020（健康 codes，L0=207，z-gap 0.005）。权威记录 + 修改索引见 [e48_toys_main_codes_provenance_fix.md](e48_toys_main_codes_provenance_fix.md)。

| codes 来源 | NDCG@20 | R@20 |
|---|---|---|
| 256 塌缩（seed2024） | 0.0367 ± 0.0006 | 0.0873 |
| **256 健康（seed2025）** | **0.0372 ± 0.0012** | **0.0906** |
| 512（Adaptive，seed2024） | 0.0381 ± 0.0023 | 0.0914 |

**判定 (a)：** 健康 256（0.0372）≈ 512（0.0381），std 重叠无统计差异 →

不是"Toys 需要 512"。Toys 的瓶颈 = **码本健康度**，不是容量。

## 3. 为什么推翻：根因拆解

1. **"塌缩"的归因错了**：E43 把 L0 低占用 + 大 z-gap 归因于"256 容量不够"。
   E45 证明同样的 256，换个初始化就 59–76% 用码、z-gap ≤ 0.004。所以塌缩是
   **优化/初始化事件（allocation collapse）**，不是容量数值事件（E2 早已提示根因在
   allocation，E45 补上了"allocation 本身对初始化敏感"这一环）。
2. **"扩容"是歪打正着**：K0 256→512 时种子没换，但 512 那次恰好落到健康分配上。
   扩容之所以"有效"，是因为**改变了优化轨迹从而避开了这次崩坏**，不是因为"给足了容量"。
   与其扩容量，不如直接 **reseed 重训**（RQ-VAE ~8 min/次，0 T5）——更便宜、更对症。
3. **"容量剂量-响应"是假象**：0.093→0.0045→0.0003 ↔ NDCG 0.0367→0.0381→0.0384 的"传导一致性"
   其实刻画的是 **坏状态 vs 健康状态**（二元），不是"容量越多越好"（单调）。健康 256 已到 0.0372，
   与 512/1024 无差别 → 不存在"量化层平台在 512、下游平台也在 512"的剂量关系，只有
   "塌缩伤下游、健康则容量无关"的阈值关系。
4. **"结果因数据而异 {256,256,512}"不可复现**：把 seed2025/2026 喂给同一"自适应算法"，
   Toys 会停在 256 → 输出变成 {256,256,256-or-512-看种子}。一个输出依赖单次随机种子的
   "自适应算法"，作为方法主张是脆弱的。

## 4. 保留什么、推翻什么（逐条）

### ✅ 保留（诊断与观测层面，仍然成立）

| # | 保留项 | 说明 |
|---|---|---|
| R1 | **z-gap 是坏码本的唯一探测器** | 塌缩码本 recon MSE 与健康几乎无差（recon 不可见），只有 z-gap(0.093) 揪出；真实代价 NDCG −1.4% / R@20 −3.8%（相对健康 256）。这是最硬的事实，反而因"任何种子都可能塌"而更重要。 |
| R2 | **判据精度叙事**（E44 §10.3 朴素判据失效表） | z-gap 6 数据集最终判定全对；MI 塌缩但无损→不触发、Electronics 100% 用码但扩容无效→复测拒绝、Sport 压测到 1/4 容量仍不误触发。**这套是判据（检测器）的精度，与扩容动作无关，全部保留。** |
| R3 | **五态/多态分类**（塌缩≠容量不足） | "塌缩但无损（MI）"、"饱和但无效（Electronics）"、"容量压小仍无损（Sport）"仍然正确；只把 Toys 从"容量不足态"改名为"**分配崩坏态（初始化敏感）**"。 |
| R4 | **根因在 allocation 而非容量数值**（E2/E3/Sport 压测互证） | 保留；E45 补强为"allocation 崩坏对初始化敏感"。 |
| R5 | **ε=0.01 阈值 / 健康侧裕度分析**（E44 §10.4） | 阈值本身的合理性分析保留（健康侧 3 倍裕度）；但"收敛到 K0\*=512"的表述改为"收敛到健康分配"。 |
| R6 | **负面结果**（转移熵 predictor 方向颠倒等） | 保留（与判据必要性论证有关）。 |
| R7 | **坏种子代价的量化** | 坏码本让 NDCG 掉 1.4%、R@20 掉 3.8%（相对）——这是"健康量化器诊断"叙事的剂量依据。 |

### ❌ 推翻（方法/叙事层面，论文不得再主张）

| # | 推翻项 | 新口径 |
|---|---|---|
| O1 | **"Toys 系统性容量不足、需 K0\*=512"** | Toys 256 健康种子即近无损；无系统性容量需求。 |
| O2 | **"扩容 → 推荐层稳健 +3.8% / +4.7%"**（Q3 卖点） | +3.8% 来自修好坏种子；健康 256 ≈ 512（无统计差异）。撤下或改写为"修复坏码本可挽回 ~1.4% NDCG / 3.8% R@20"。 |
| O3 | **"自适应算法 = 扩容动作"作为方法贡献** | 动作改为更便宜的 **reseed**（或死码复活）；扩容降级为可选项，不再声称必要/最优。 |
| O4 | **"量化层平台=下游平台"传导一致性（剂量-响应）** | 改为"健康 vs 塌缩"二元阈值关系；不再声称 z-gap 随容量单调下降可预测下游增益曲线。 |
| O5 | **"自适应输出因数据而异 {256,256,512}"** | 不可复现（依赖种子）；如实报告为"单种子下落到 512，多种子下 256 即健康"。 |
| O6 | **"从可选优化升级为必要保护"的措辞若以扩容为手段** | 保留"必要保护"的结论，但手段是 **z-gap 事后检测 + reseed 兜底**，不是扩容。 |

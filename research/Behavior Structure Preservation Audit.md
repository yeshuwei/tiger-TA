# 任务：Semantic ID 行为结构保留研究的 P0 只读代码审计

## 1. 研究背景

当前研究问题：

**训练数据定义的局部行为关联结构，在行为向量构建、内容—行为融合、RQ-VAE 逐层量化和最终 Semantic ID 离散编码过程中发生了哪些变化？这些变化与生成式推荐性能有什么关系？**

当前研究处于机制诊断与实证研究阶段。暂不设计新模型、新损失函数，不预设 RQ-VAE 一定破坏行为结构，也不预设结构保留越高推荐效果一定越好。

已知项目背景（必须以仓库实际代码为准）：

- 数据集：Amazon Beauty、Sport、Toys。
- 内容向量：Sentence-T5-base，预计 768 维。
- 行为结构：训练集用户序列构建的局部对称共现关系，`window=3`、`half_window=1`、`min_cooccur=1`。
- 行为向量：PPMI + 截断 SVD，预计 128 维。
- 融合：分别 LayerNorm 后拼接，预计 896 维。
- RQ-VAE：预计 latent 32 维，3 层 RVQ，每层 codebook size 256。
- SID：3 个 RVQ code token，加独立的 collision-bit token。
- 已知文件线索：`behavior_variants.py`、`per_level_alignment_diagnostic.py`，以及此前出现过的容量扫描脚本和结果文件。实际路径均需核实。

## 2. 本次任务目标

只做 P0：审查现有代码、配置、checkpoint、日志和结果文件，盘点哪些实验能力已经存在，哪些部分可以复用，哪些确实缺失。

### A. 审查范围

1. 数据划分、训练序列口径及潜在数据泄漏。
2. 原始共现矩阵、PPMI、SVD 行为向量的构建与保存。
3. 内容向量、融合向量及 item_id 对齐。
4. RQ-VAE Encoder latent 的提取。
5. RVQ 各层累计量化向量、各层 code、residual 的定义和提取方式。
6. 最终 SID token 的生成、映射、碰撞处理及 collision bit。
7. `per_level_alignment_diagnostic.py` 的输入、输出、指标计算及限制。
8. Top-K overlap、Spearman、edge AUC 等指标的现有实现。
9. SID prefix 诊断能力。
10. Codebook capacity scan 的配置、checkpoint、已有结果及容量变化范围。
11. 生成式推荐评估脚本、日志、随机种子及指标口径。

### B. 重点核实的问题

- 所有表示能否按相同 item_id 顺序严格对齐？
- 原始行为关系、PPMI、SVD 向量分别在哪里构建和保存？
- 各量化阶段输出究竟是累计重构、单层 code，还是 residual？必须依据实际代码说明。
- 是否能在不重训的条件下导出各阶段表示？
- collision bit 是否被错误地作为普通量化层纳入诊断？
- 行为图、PPMI、SVD 是否仅使用训练集交互构建？
- 容量扫描是只修改第一层 K0，还是同时修改全部三层？其他配置是否一致？
- 容量变化后是否需要重新生成 SID 并重新训练 T5，才能公平比较推荐效果？
- 现有指标实现是否存在采样偏差、零向量问题、重复物品对、数据泄漏或物品索引错配？

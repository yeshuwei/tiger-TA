  `.order.npy`（次级键 = canonical index **升序**）与 `.order_flip.npy`（**降序**）。

> §7 的邻域指标（Neighbor Recall@K / Jaccard@K / Overlap@K）一律**不在本表计算**，
> §4.3 的 `> 0.005` 判定必须等 P1.3。**本表不构成任何结论。**

## 读法（三条，均为描述性）

1. **`q1`：集合几乎必然改变**（99.7–99.9% 的 query），且边界间隙恒为 `0`
   ⇒ 完全是 `q1` 的**精确同值**（§4.2：`q1` collapse 0.983–0.986）导致的真并列，
   与浮点无关。⇒ 任何**含 `q1` 的空间对**在 §4.3 检查中必然被激活。
2. **`q12`：~27–32% 的 query 集合改变**，边界间隙 ≤ 1.8e-7（多数为 0）
   ⇒ 主体是精确同值（collapse 0.246–0.288），少数是**ulp 级近并列**。
3. **其余空间（`behavior128` / `z_norm` / `q123` / `content768` / `input896`）：
   0–23 个 query（≤ 0.02%）**，且间隙 ≤ 1.2e-7 ⇒ 全部是 float32 **末位 ulp** 效应。

## 浮点保真度说明（**供 P1.3 参考，非协议变更**）

`collect_topk(..., flip=True)` 通过**逐位重排候选列**（`np.ascontiguousarray(Xn[cand])`）
实现次级键翻转，并对两套列序**各跑一次 GEMM**。实测：同一 problem size 下，
列序置换会使 **极少数元素的 GEMM 舍入结果相差 1–2 ulp**（≤ 1.8e-7，
`np.array_equal` 为 False）；单行 GEMM 则逐位一致。

**影响面**：只有「第 K 名与第 K+1 名相似度之差 ≤ 1.2e-7」的 query 可能因此翻转排序，
即上表第 3 条所述的 ≤ 0.02%；对精确并列（间隙 = 0）无影响。

**若需完全消除**（可选，**须由用户决定，本工具未改**）：先算一次 `S`，
再以 `S[:, ::-1]`（纯视图、无算术）生成翻转列序上的相似度，
两套邻居序即由**同一个 `S`** 导出，差异将**只**来自次级键方向。
